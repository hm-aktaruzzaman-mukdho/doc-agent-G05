Here's what I'd change, in priority order:

**1. Add a layout-detection pass before OCR** (biggest win)
Instead of `page.get_pixmap()` → OCR the whole page, first segment the page into regions: text blocks, image/map regions, and table regions. You can do this cheaply with:
- `page.get_text("dict")` in PyMuPDF gives you block-level bounding boxes even on pages with mixed native+image content — use this to detect where images sit vs. text.
- For pages that are fully scanned (no native layer), use a lightweight layout model like `doclayout-yolo` or even simple heuristic column/whitespace-gap detection (large blank horizontal bands = table row separators; large image blocks = maps/figures).

Then route each region type differently:
- **Prose/paragraph regions** → your existing EasyOCR line-reconstruction logic (this part is already solid).

- **Table regions** → this is where EasyOCR line-grouping breaks hardest. Detect table cells via ruling lines (`cv2.HoughLinesP` on the region) or whitespace-gap column detection, OCR cell-by-cell, and emit as Markdown table syntax, not free text.

```python
def _run_qwen_generate(pil_image: Image.Image, prompt: str, model, processor) -> str:
    # 1. SAFETY VALVE: Cap max pixels to prevent VRAM explosion
    # 1.2 Megapixels is safe for a 16GB T4 while maintaining high readability
    max_pixels = 1200 * 1200 
    w, h = pil_image.size
    if w * h > max_pixels:
        scale = (max_pixels / (w * h)) ** 0.5
        new_w, new_h = int(w * scale), int(h * scale)
        pil_image = pil_image.resize((new_w, new_h), Image.Resampling.LANCZOS)

    messages = [
        {
            "role": "user",
            "content": [
                {"type": "image", "image": pil_image},
                {"type": "text", "text": prompt},
            ],
        }
    ]
    text_prompt = processor.apply_chat_template(
        messages, tokenize=False, add_generation_prompt=True
    )
    inputs = processor(
        text=[text_prompt], images=[pil_image], padding=True, return_tensors="pt"
    )
    inputs = {k: v.to(model.device) for k, v in inputs.items()}

    with torch.no_grad():
        generated_ids = model.generate(
            **inputs,
            max_new_tokens=MAX_QWEN_NEW_TOKENS,
            do_sample=False,
            temperature=None,
            top_p=None,
            top_k=None,
        )
        
    trimmed = [
        out[len(inp):] for inp, out in zip(inputs["input_ids"], generated_ids)
    ]
    output_text = processor.batch_decode(
        trimmed, skip_special_tokens=True, clean_up_tokenization_spaces=False
    )

    # 2. AGGRESSIVE CLEANUP: Free the massive generation activations immediately
    del inputs, generated_ids, trimmed
    if torch.cuda.is_available():
        torch.cuda.empty_cache()

    return output_text[0].strip()

```

### Why this fixes it:

1. **Dynamic Resizing:** If an extremely tall table or wide map sneaks through, the PIL resize logic shrinks it proportionally so it never exceeds ~1.44 million pixels, guaranteeing the visual tokens stay well within the T4's limits.
2. **Immediate Garbage Collection:** `torch.cuda.empty_cache()` at the end of the function ensures the 4-8 GB of activation memory used *during* generation is instantly returned to the GPU, so the next EasyOCR or Qwen call starts with a clean slate.

## Core Components Deep-Dive

### 1. Data Ingestion & Orchestration

* **Driver:** The script reads books sequentially and writes pages to disk one at a time. This prevents RAM bloat, meaning processing a 500-page book takes the exact same amount of memory as a 5-page book.
* **Native Text Recovery:** Before doing any OCR, PyMuPDF checks if the publisher included an actual text layer. If it finds one, it skips the heavy prose OCR entirely, saving massive amounts of compute time.

### 2. Computer Vision Layout Analysis (OpenCV)

Instead of loading an AI model to detect page layouts (which would consume precious VRAM), the pipeline uses classical computer vision.

* It renders the page into a grid of pixels.
* It uses **Morphological Transformations** (`cv2.morphologyEx`) to stretch horizontal and vertical dark pixels. Where these stretched lines intersect, the algorithm identifies a grid (a table or calculation block) and draws a bounding box around it.

### 3. The Hybrid Inference Engine

This is where the pipeline optimizes for the Kaggle T4 GPU:

* **EasyOCR (The Grunt):** Sits in VRAM taking up only ~400MB. It runs over standard paragraphs rapidly.
* **The Quality Gate:** If EasyOCR returns text with a confidence below 70%, or if >15% of the output consists of garbled symbols (which EasyOCR sometimes does on mixed English/Bangla text), the pipeline traps the error.
* **Qwen2.5-VL-3B (The Specialist):** Loaded in `float16`, this model takes up about 6GB of VRAM. It acts as an escalation path. It is only called for highly complex structures (Maps, Tables) or when EasyOCR fails the Quality Gate.

### 4. Memory Management (T4 Safeguards)

Because VLMs allocate massive blocks of memory dynamically based on how many pixels you feed them, the pipeline features two critical fail-safes:

* **The 1.2 Megapixel Cap:** Using standard Lanczos resampling, any image that would crash the GPU is proportionally shrunk before the model sees it.
* **Aggressive Garbage Collection:** `torch.cuda.empty_cache()` is called explicitly after Qwen generates text, instantly destroying the heavy activation tensors so they don't fragment the GPU's memory pool.

### Part 1: The Indexing Pipeline (`build_index.py`)

This script reads your OCR'd `.md` files, logically chunks them by headers, embeds them using a strong multilingual model, and saves a FAISS vector index to disk.

```python
%%writefile build_index.py
import os
from pathlib import Path
from langchain.text_splitter import MarkdownHeaderTextSplitter, RecursiveCharacterTextSplitter
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

# ==============================================================================
# CONFIGURATION
# ==============================================================================
MD_DIR = Path("/kaggle/working/")
INDEX_DIR = Path("/kaggle/working/bangla_books_faiss_index")

# Using a multilingual model that performs excellently on Bengali
EMBEDDING_MODEL = "sentence-transformers/paraphrase-multilingual-mpnet-base-v2"

def main():
    md_files = list(MD_DIR.glob("*.md"))
    if not md_files:
        print(f"No Markdown files found in {MD_DIR}")
        return

    print(f"Found {len(md_files)} Markdown files. Starting ingestion...")

    # 1. Define Markdown hierarchy based on our ocr_helper.py output
    headers_to_split_on = [
        ("#", "Book_Title"),
        ("##", "Page_Number"),
        ("###", "Section_Type"),
    ]
    markdown_splitter = MarkdownHeaderTextSplitter(headers_to_split_on=headers_to_split_on)

    # 2. Fallback splitter for very long text blocks (e.g., a massive 3-page chapter)
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=768, 
        chunk_overlap=100,
        separators=["\n\n", "\n", "।", " ", ""] # Bangla sentence ending (Dari) included
    )

    all_chunks = []

    # 3. Read and Chunk
    for file_path in md_files:
        print(f"Chunking: {file_path.name}")
        with open(file_path, "r", encoding="utf-8") as f:
            md_text = f.read()
        
        # Split by markdown headers
        md_header_splits = markdown_splitter.split_text(md_text)
        
        # Further split long paragraphs
        splits = text_splitter.split_documents(md_header_splits)
        
        # Inject the source file name into metadata
        for split in splits:
            split.metadata["Source_File"] = file_path.name
            
        all_chunks.extend(splits)

    print(f"Total chunks created: {len(all_chunks)}")

    # 4. Embed and Store
    print(f"Loading embedding model: {EMBEDDING_MODEL}...")
    embeddings = HuggingFaceEmbeddings(
        model_name=EMBEDDING_MODEL,
        model_kwargs={'device': 'cuda'} # Will use GPU if available
    )

    print("Generating embeddings and building FAISS index (this may take a moment)...")
    vectorstore = FAISS.from_documents(all_chunks, embeddings)
    
    # 5. Save to disk
    vectorstore.save_local(str(INDEX_DIR))
    print(f"FAISS index successfully saved to: {INDEX_DIR}")

if __name__ == "__main__":
    main()

```

### Understanding the Score in FAISS:

Since `normalize_embeddings=True` was set during indexing:

* FAISS reports **L2 Distance**.
* **Lower is better** (a score closer to `0.0` represents higher semantic similarity / closer match).
* If you prefer a normalized **Similarity Score (0.0 to 1.0, where higher is better)**, you can replace `similarity_search_with_score` with `vectorstore.similarity_search_with_relevance_scores(query, k=3)`.
